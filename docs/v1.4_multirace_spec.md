# v1.4 仕様書 — 複数レース収集（Pro）

作成: 2026-07-21 ／ 状態: 実装済・Playwright 検証済・審査未提出

## 1. 目的

ユーザーの**手間削減**。1 レースずつコピペを往復する代わりに、気になるレースを見ながら「収集」に貯め、**まとめて 1 出力**にする。Pro の優良機能。

（※ 意図的に「全レース自動一括取得」は作らない。法的・規約・privacy の理由は §5。）

## 2. UX フロー

1. ユーザーが netkeiba / JRA のレースページ（出馬表 or 結果）を開く
2. 「データ抽出」→ 従来どおり整形。加えて **「＋ このレースを収集に追加」ボタン**が出る
3. 収集に追加すると **「今日の収集」リスト**（場・R・レース名）に溜まる（件数バッジ付き）
4. **「まとめて出力（コピー）」** で、収集した全レースを現在のフォーマットで 1 つに結合してコピー
   - Markdown / CSV: 各レースを `---` で区切って連結
   - **AI 分析用: 「以下 N レースを比較し、最も"買い"に値する 1 レース・1 頭を選んでください」＋各レースの表** ＝「今日の1本」を選ぶプロンプトに最適化
5. 各項目は × で個別削除、「クリア」で全消去

## 3. 課金の線引き

- **Free**: 従来どおり 1 レース抽出・コピー・履歴
- **Pro**: 複数レース収集＋一括出力（「収集に追加」クリックで Free はアップグレードカード `kind:"collection"` を表示）

## 4. データモデル・実装

- 保存: `chrome.storage.local["collectedRaces"]` = 抽出済み race データ配列（生の `{raceInfo, horses}`）
- 重複防止: `raceKey = date|track|raceNumber|raceName`
- 出力時に現在フォーマットで `formatData` を各レースへ適用（`buildCombined`）
- 主な関数（popup.js）: `loadCollection` / `saveCollection` / `addToCollection` / `renderCollection` / `buildCombined` / `setupCollectionUI`
- 計測: `collect_add` / `collection_export` / `pro_locked_click{kind:"collection"}`
- UI: popup.html の `#collectionSection`・`#btnCollect`、styles.css の `.collection-*` / `.btn-collect` / `.btn-collection-export`

## 5. 法的・規約・privacy の設計判断（重要）

**採用したのは「ユーザー巡回＋集約」型。自動バックグラウンド取得は採用しない。**

- 収集対象は **ユーザーが自分で開いたレースページの DOM のみ**。読み取りは netkeiba・JRA の対象 URL に限定した `content_scripts`（host matches）＋ `chrome.scripting.executeScript` で行い、拡張が見ていないレースを勝手に取りに行かない＝スクレイピング/クローリングに当たらない。netkeiba 利用規約・著作権（データベース著作物）・Chrome ウェブストアのスクレイピング禁止ポリシーの**いずれにも触れない足場**を維持。
- データは `chrome.storage.local` に貯めるだけ＝**外部送信なし**（fetch/XHR ゼロ・ライセンス認証もローカル）。フッターの「DOM 読み取り専用・外部送信されません」は**引き続き真**。
- **権限は v1.3.3 から不変**：`activeTab` / `clipboardWrite` / `downloads` / `scripting` / `storage`。新規 host 権限の追加なし＝**既存ユーザーへの再承認プロンプトなし**でスムーズに自動更新。
- ブランド（実直・信頼）と矛盾しない。
